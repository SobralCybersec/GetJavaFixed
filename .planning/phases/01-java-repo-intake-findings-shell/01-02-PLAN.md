## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user→folder picker | User-selected directories enter the app from an OS-native dialog |
| frontend→native readiness | UI state depends on the typed readiness DTO returned by Rust |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04 | Spoofing | `JavaRepoHome` readiness UI | mitigate | Render support state only from the native DTO and exact blocked-state copy; do not infer support from path strings. |
| T-01-05 | Elevation of Privilege | dialog + invoke bridge | mitigate | Restrict folder selection to the official dialog plugin and pass all selected paths through `java_repo_readiness`. |
| T-01-06 | Denial of Service | `App.tsx` first-run routing | accept | Keep the intake route lightweight and synchronous except for explicit picker/readiness actions; no background scanning in this plan. |
| T-01-SC | Tampering | npm/cargo install surface | mitigate | Use only `@tauri-apps/plugin-dialog` and `tauri-plugin-dialog`, both marked Approved in the package legitimacy audit. |
</threat_model>
